# Privacy

An optional Windows pinned binding saves only the selected conversation ID/title in `manual-binding.json`, with a separate `pinned-layout.json`. The user's explicit selection replaces accessibility tracking until unpinned; it does not change the underlying Codex conversation.

The HUD runs locally and makes no external network requests during normal use. The first source-overlay launch downloads public Qt dependencies into a private virtual environment; bundled apps need no dependency download. The browser interface communicates only with its own `127.0.0.1` HTTP service. It does not read `auth.json`, authentication tokens, passwords, account credentials, or environment files. It does not request account quota information.

It reads the `threads` table in a compatible local Codex `state_*.sqlite` database using SQLite read-only mode, session metadata and the optional `session_index.jsonl` title index. The Windows native HUD reads the selected chat's recent JSONL tail and the accessibility header of Codex windows. The macOS/Linux HUD reads a selected or explicitly latest-active chat without accessibility access. Historical statistics stream the selected chat's complete local rollouts, including resumed segments and archived logs. Explicit `--log` inputs are read only when supplied by the user.

The optional Qt strip stores derived state, binding and layout in a separate `overlay-runtime` subdirectory. A user-only local socket and instance lock handle repeat-launch recovery. Its browser service has the same loopback/token restrictions. These private files and all real conversation data are excluded from public packages.

Message-range selection necessarily indexes user messages in memory and displays matching excerpts in the local browser. It does not display assistant bodies. Up to three conversations' history indexes are kept in process memory; exiting the process releases them. Selected message excerpts are not written to the saved range result. Terminal `stats.py --messages` prints user excerpts to the user's terminal; other reports contain derived statistics. None of this data is uploaded.

The browser service binds IPv4 loopback only, chooses an available port, checks Host/Origin, and requires a random per-process token for data APIs. The token is passed in the URL fragment and sent in a local request header; no access logs, external assets, CDNs or trackers are used. Requests cannot name arbitrary file paths. Do not share the printed link or `dashboard.json`. An explicitly configured SSH forward carries traffic to a host chosen by the user; it does not expose a public web server.

Derived JSON in `%LOCALAPPDATA%\CodexTokenHud\runtime` includes chat titles, IDs, model, token counts, timing, source file paths, recent thread metadata, refresh receipts and a confirmed range snapshot. Saved layout and optional settings are in the same data directory. The dashboard uses `~/Library/Application Support/CodexTokenHud` on macOS, or `${XDG_STATE_HOME:-~/.local/state}/codex-token-hud` on other systems. `CODEX_TOKEN_HUD_HOME` can override the data directory. These files stay on the computer but are private. Do not upload them, real rollout logs, database files, or screenshots containing chat text in bug reports.

The source repository excludes local settings, runtime data, legacy layouts, inspection extracts, downloads, and build artifacts. Packaging copies an explicit allowlist and checks the archive for prohibited private paths. Packaging downloads the official Python runtime over HTTPS and verifies its pinned SHA256; this is a developer build operation, not application runtime traffic.

Exiting the HUD ends its collector. Uninstall removes this copy's optional logon task and desktop shortcut but preserves saved user data. If you want to remove the saved data too, exit the HUD first and manually delete `%LOCALAPPDATA%\CodexTokenHud`. The HUD does not delete or alter Codex chats.
